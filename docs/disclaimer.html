3. What the extension does with what it reads

It reads the visible text of the table you asked for, on the tab you activated, and turns it into a file. It sends nothing anywhere. It keeps no copy of the table after the export completes. The full data inventory is on the privacy policy page.

4. Limits that belong to the browser, not to this extension

Each row below is a hard boundary imposed by Chrome, by the same-origin model, or by how a page was built. No extension running under four permissions can cross any of them. They are listed so that a failure is never a mystery.

SituationWhat happensWhy it is unavoidable
chrome:// pages, the Chrome Web Store, and other protected origins Not readable at all Chrome refuses script injection into these origins for every extension, regardless of permissions.
Data drawn into <canvas> — charts, virtualised grids, PDF viewers, most dashboards No table is found A canvas holds pixels, not text nodes. There is no DOM to read, and reading pixels would require a screenshot and optical recognition, which is out of scope.
Cross-origin iframes Skipped, and counted in the scan summary The same-origin policy blocks access to a frame served from another origin unless the extension holds host permissions for it — which this one deliberately does not.
Closed shadow roots Invisible to detection A closed root exposes no shadowRoot reference. There is nothing to attach to.
Infinite scroll and paginated tables Only what is currently in the DOM is exported The extension reads the document, not the site's data source. Rows that do not exist yet cannot be read, and following pages would need host permissions.
Tables behind a login or paywall you have not passed Not present, so not exported If the page has not rendered the rows, they are not in the document.
Pages that fail to load, or load after you scan Scan again once the table appears Detection is a snapshot of the DOM at the moment you press Scan.
Text that only appears on hover or on click Not exported Only rendered, visible text is read — deliberately, so that tooltips and hidden duplicate markup cannot pollute a cell.

5. The 500-row limit

Each table exports its first 500 rows, and the header row counts as one of them. This is a fixed property of the free build, stated in the extension's description, shown as a 500 max badge beside the table's true size before you export, and reported in the status line afterwards as, for example, "first 500 of 1,001 rows".

The limit is not a trial, not a quota, and not a lever. There is no purchase that removes it, and it does not reset or expire. Rows are cut whole: the exported matrix stays rectangular, so no row is ever left short or misaligned.

6. Accuracy of an export

The extension copies what the page displays. It does not verify the page. Specifically:

  • Numbers are written as text, so a leading zero survives — and so a value the site displayed as 1,234 stays exactly that, rather than being silently reinterpreted.
  • Cells beginning with =, +, - or @ are prefixed with an apostrophe so a spreadsheet treats them as text. If you want the raw value, turn the safety toggle off in the cleaning panel.
  • Hidden elements, nested tables and form-control markup are excluded on purpose, so that duplicate mobile markup does not double every cell.
  • Merged cells are expanded so that every covered position carries the same value.
